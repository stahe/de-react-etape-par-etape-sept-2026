    Zunächst prüft [tsc --noEmit] die Typen des gesamten Projekts: [Vite] tut dies nicht; es entfernt lediglich die Syntax von [TypeScript]. Ein Typfehler bricht den Build ab. Anschließend erstellt [Vite] die gesamte Anwendung im Ordner [dist/]: eine Seite [index.html], Stylesheets und optimierte [JavaScript]-Dateien:

    • [libraries-....js]: der Code der Bibliotheken ([React], [React Router], [TanStack Query], [i18next] ...), durch die Konfiguration von [vite.config.ts] in einer eigenen Datei abgelegt. Er ändert sich selten: Von einer Version der Anwendung zur nächsten behält der Browser ihn im Cache. [libraries-....css]: das Stylesheet von [Bootstrap];
    • [index-....js]: UNSER Code, verwendet für die sofort geladenen Seiten (Anmeldung, Terminkalender) und den Rest der Anwendung;
    • Jede bei Bedarf geladene Seite ([lazy], siehe [routes.tsx]) hat ihre eigene Datei ([MyAccount-....js] ...), die beim ersten Besuch heruntergeladen wird; [PersonFields-....js] und [persons.config-....js] enthalten Code, der mehreren dieser Seiten gemeinsam ist;
    • Beim Start lädt der Browser einmalig etwa 170 KB herunter, vom Server komprimiert (Spalte gzip), davon 150 KB für die Bibliotheken;
    • Der Name jeder Datei enthält einen Hash ihres Inhalts ([index-D-CLbbe-.js]): Eine neue Version hat einen anderen Namen, sodass ein Browser nie eine veraltete Version zwischenspeichern kann. Nur [index.html] behält ihren Namen: Diese Datei verweist auf die anderen.

    Sie können die erstellte Version mit [npm run preview] ausprobieren (http://localhost:4173, mit demselben Proxy zum JSON-Server).

    2. Auf den Server hochladen. Kopieren Sie den INHALT des Ordners [dist/] in einen Ordner [client/] im Stammverzeichnis des JSON-Servers ([rdvmedecins-nestjs-json/client/index.html], [rdvmedecins-nestjs-json/client/assets/...]) und starten Sie den Server neu. Er zeigt an:

    1
2
    [Nest] LOG [RdvMedecins] React client served from .../rdvmedecins-nestjs-json/client
[Nest] LOG [RdvMedecins] JSON server started: http://localhost:8080/api

    Die vollständige Anwendung ist nun unter http://localhost:8080 verfügbar. Der Server liefert die Dateien des Clients aus und gibt für jede andere URL außerhalb von /api [index.html] zurück: Das Neuladen der Seite /schedule funktioniert (der Browser des Clients zeigt sie an). Für Neugierige: Diese Aufgabe übernimmt die Datei [src/web/client-spa.ts] auf dem Server.

    3. In einer echten Produktionsumgebung vergessen Sie nicht die Datei [.env] auf dem Server:

    • ein langes, zufälliges [JWT_SECRET];
    • ein leeres [CAPTCHA_TEST];
    • [COOKIE_SECURE=true] wenn die Website über HTTPS ausgeliefert wird (das muss sie: Es werden Passwörter übertragen);
    • [TRUST_PROXY=true] wenn der Server hinter einem Proxy ([nginx] ...) steht, damit die Begrenzung der Versuche die tatsächliche IP-Adresse der Clients sieht.

    Anschließend starten wir den kompilierten Server: [npm run build], gefolgt von [npm run start:prod].
