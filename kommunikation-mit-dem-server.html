    8. Kommunikation mit dem Server

    Die Beispiele in diesem Kapitel fragen den JSON-Server von [RdvMedecins] ab: Er muss laufen ([npm run start:dev] im Ordner [rdvmedecins-nestjs-json]) auf Port 8080, gleichzeitig mit dem Entwicklungsserver [Vite] auf Port 5173.

    8.1. Beispiel 22: Eine erste HTTP-Anfrage

    8.1.1. Der Proxy des Entwicklungsservers

    Die Seite dieses Beispiels stammt von http://localhost:5173 (dem Entwicklungsserver [Vite]); die API befindet sich unter http://localhost:8080. Für einen Browser sind dies zwei verschiedene Ursprünge (der Port ist Teil des Ursprungs). Aus Sicherheitsgründen erlaubt ein Browser einer Seite jedoch nicht, Antworten eines anderen Ursprungs zu lesen, es sei denn, der Server erlaubt dies ausdrücklich (der Mechanismus namens CORS). Und eine Anfrage an einen anderen Ursprung enthält keine Cookies (und damit auch nicht das Token), es sei denn, der Code verlangt es ([credentials: 'include']) UND der Server akzeptiert dies, wiederum über CORS.

    Anstatt den Server für andere Ursprünge zu öffnen, leiten wir die API-Anfragen über den Entwicklungsserver [Vite] um. Das ist der Proxy , der in der Datei [vite.config.ts] der Beispiele deklariert ist (siehe Beispiel 01):

// 22-fetch/src/App.tsx - eine erste HTTP-Anfrage an den Server
// -------------------------------------------------------------------------
// Der JSON-Server von RdvMedecins muss gestartet sein (Port 8080). Wir fragen ihn nach
// einem CAPTCHA: GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//   - fetch(url): die Browserfunktion, die eine HTTP-Anfrage sendet.
//     Sie liefert ein PROMISE der Antwort; response.json() ein Promise
//     des aus JSON umgewandelten Bodys. React hat keinen eigenen HTTP-Client;
//   - die Adresse ist RELATIV (/api/captcha): Die Anfrage geht an den
//     Server der Seite, den von Vite (Port 5173), der sie dank seines Proxys an den
//     JSON-Server (Port 8080) weiterreicht (vgl. vite.config.ts);
//   - drei anzuzeigende Zustände: in Bearbeitung, erfolgreich, fehlgeschlagen.
// =========================================================================

import { useEffect, useState } from 'react';

// was GET /api/captcha zurückliefert
interface Captcha {
  id: string;
  svg: string;
}

const captchaStyle = { display: 'inline-block', border: '1px solid #dee2e6', borderRadius: '0.375rem' };

export default function App() {
  const [captcha, setCaptcha] = useState<Captcha | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);
  const [requestCount, setRequestCount] = useState(0);
  // jeder Klick auf "Another image" ändert diese Zahl, wodurch der Effekt neu gestartet wird
  const [demand, setDemand] = useState(0);

  useEffect(() => {
    // AbortController: das Mittel, um eine laufende Anfrage ABZUBRECHEN
    const cancellation = new AbortController();
    setLoading(true);
    setError(null);
    fetch('/api/captcha', { signal: cancellation.signal })
      .then(async (response) => {
        // fetch weist eine Fehlerantwort (4xx, 5xx) NICHT zurück: ok wird geprüft
        if (!response.ok) {
          throw new Error(`the server answered ${response.status} ${response.statusText}`);
        }
        const c = (await response.json()) as Captcha;
        setCaptcha(c);
        setRequestCount((n) => n + 1);
        setLoading(false);
      })
      .catch((e: Error) => {
        if (e.name === 'AbortError') return; // Anfrage abgebrochen: nichts anzuzeigen
        setError(e.message);
        setCaptcha(null);
        setLoading(false);
      });
    // das Cleanup BRICHT die Anfrage ab, wenn der Effekt neu gestartet wird oder wenn die
    // Komponente vor der Antwort verschwindet. In der Entwicklung führt StrictMode
    // den Effekt beim Start zweimal aus: Die erste Anfrage wird
    // abgebrochen (Tab Network: "canceled"), nur die zweite zählt.
    return () => cancellation.abort();
  }, [demand]);

  return (
    <div className="container py-4" style={{ maxWidth: 640 }}>
      <h1 className="h3 mb-3">Example 22 - a first HTTP request</h1>
      <div className="card p-3">
        {loading && <p className="text-muted">Loading...</p>}
        {error && (
          <div className="alert alert-danger mb-3">
            Unable to get a captcha: {error}.<br />
            Is the RdvMedecins JSON server started (port 8080)?
          </div>
        )}
        {captcha && !loading && (
          <>
            {/* dangerouslySetInnerHTML: eine Zeichenkette als HTML einfügen */}
            <div className="mb-2"><div style={captchaStyle} dangerouslySetInnerHTML={{ __html: captcha.svg }} /></div>
            <p className="small text-muted">id: <code>{captcha.id}</code></p>
          </>
        )}
        <button className="btn btn-primary align-self-start" disabled={loading} onClick={() => setDemand((d) => d + 1)}>
          Another image
        </button>
        <p className="small text-muted mt-2 mb-0">
          {requestCount} successful request(s) - open the Network tab of the developer tools (F12).
        </p>
      </div>
    </div>
  );
}
    • Zeilen 19–22: was [GET /api/captcha] zurückgibt;
    • Zeilen 27–30: drei anzuzeigende Zustände: in Bearbeitung, erfolgreich (das CAPTCHA), Fehler;
    • Zeile 32: eine Anfragenummer: Jeder Klick auf „Another image“ erhöht sie, wodurch der Effekt erneut ausgelöst wird;
    • Zeilen 34–61: Die Anfrage ist ein Effekt: Er synchronisiert die Komponente mit dem Server, bei der ersten Anzeige und danach bei jeder neuen Anfrage:
      • Zeile 36: Ein [AbortController] ermöglicht es, eine ausstehende Anfrage abzubrechen: Sein [signal] wird an [fetch] übergeben;
      • Zeile 39: [fetch(url)] sendet eine Anfrage (GET) und gibt ein Promise für die Antwort zurück. Die Adresse ist RELATIV: Die Anfrage wird an den Server der Seite gesendet, [Vite], der sie an den JSON-Server weiterleitet;
      • Zeilen 42–44: ACHTUNG: [fetch] weist das Promise NICHT ab, wenn es eine Fehlerantwort (4xx, 5xx) erhält; sein Promise wird nur abgewiesen, wenn KEINE Antwort eintrifft (Netzausfall). Daher wird [response.ok] geprüft (true bei einem 2xx-Code);
      • Zeile 45: [response.json()] liest den Body und wandelt ihn aus JSON um (ein weiteres Promise). [as Captcha]: Wir teilen [TypeScript] das Format der empfangenen Daten mit; es kann dies nicht überprüfen;
      • Zeilen 50–55: ein Fehler; [AbortError]: Die Anfrage wurde abgebrochen; es gibt nichts anzuzeigen;
      • Zeile 60: Das Cleanup BRICHT die Anfrage ab, wenn der Effekt erneut ausgelöst wird oder die Komponente vor der Antwort verschwindet. In der Entwicklung führt [<StrictMode>] den Effekt beim Start zweimal aus: Die erste Anfrage wird abgebrochen (die Registerkarte Network zeigt sie als „canceled“); nur die zweite zählt;
    • Zeile 77: Das Bild ist ein SVG-Fragment, ein String, der wie HTML eingefügt wird. [{captcha.svg}] würde den Text [<svg ...>] maskiert anzeigen. [dangerouslySetInnerHTML] fügt den String unverändert ein: Sein Name warnt vor der Gefahr. Verwenden Sie es NUR für sichere Inhalte: Dieses SVG wird von UNSEREM Server erzeugt. Bei Benutzereingaben würde es der Skript-Injektion Tür und Tor öffnen;
    • Zeile 81: eine neue Anfrage; der Effekt wird erneut ausgelöst.

    Wenn der JSON-Server nicht läuft, liefert der Proxy von [Vite] einen 500-Fehler: „Unable to get a captcha: the server answered 500 Internal Server Error.“

// 23-login/src/App.tsx - Anmeldung am RdvMedecins-Server
// -------------------------------------------------------------------------
//   1. beim Start: GET /api/auth/me - sind wir bereits angemeldet?
//      (nach einem F5 hat der Client alles vergessen; der Server liest das Cookie);
//   2. Login: POST /api/auth/login, JSON-Body { login, password,
//      captchaId, captcha }. Bei Erfolg setzt der Server das httpOnly-Cookie
//      des JWT-Tokens: Unser Code sieht es NIE (versuchen Sie
//      document.cookie in der Konsole: Es ist nicht da);
//   3. geschützte Anfrage: GET /api/doctors. Der Browser hängt das Cookie
//      von selbst an (gleicher Origin);
//   4. Logout: POST /api/auth/logout - der Server löscht das Cookie.
//
// Das Formular verwendet die ACTIONS von React 19: <form action={function}>.
// Statt onSubmit und jedes Feld zu behandeln, erhalten wir alle Werte
// des Formulars (FormData), und useActionState behält das Ergebnis der
// letzten Action (hier eine Fehlermeldung) und zeigt an, ob sie gerade läuft.
//
// Ein Cookie gehört zu einem Host (localhost) und zu einem Pfad (/api): Es
// ist daher allen Beispielen GEMEINSAM. Ist man hier einmal angemeldet, sind es die Beispiele
// 24 und 25 ebenfalls.
// =========================================================================

import { useActionState, useEffect, useState } from 'react';
import { useFormStatus } from 'react-dom';

interface User {
  login: string;
  name: string;
  role: 'ADMIN' | 'DOCTOR' | 'USER';
}
interface Doctor {
  id: number;
  title: string;
  firstName: string;
  lastName: string;
}
interface Captcha {
  id: string;
  svg: string;
}
// die Form ALLER Fehler der API
interface ApiError {
  statusCode: number;
  key: string;
  params?: Record<string, string>;
}

// die wenigen Meldungen, die dieses Beispiel braucht (Beispiel 25 verwendet i18next)
const MESSAGES: Record<string, string> = {
  'LOGIN.ERROR': 'Incorrect login or password.',
  'ERRORS.WRONG_CAPTCHA': 'The characters you typed do not match the image.',
  'ERRORS.TOO_MANY_ATTEMPTS': 'Too many failed attempts. Try again later.',
};

// eine GET-Anfrage, deren JSON-Antwort typisiert ist; ein Fehler, wenn sie nicht 2xx ist
async function read<T>(url: string): Promise<T> {
  const response = await fetch(url);
  if (!response.ok) {
    throw response; // die Antwort selbst wird „geworfen“: Ihr Status sagt, was zu tun ist
  }
  return (await response.json()) as T;
}

// der Submit-Button: useFormStatus() zeigt an, ob das Formular, das ihn ENTHÄLT,
// gerade gesendet wird (es muss daher eine eigene Komponente sein, die darin platziert ist)
function LoginButton() {
  const { pending } = useFormStatus();
  return <button className="btn btn-primary" disabled={pending}>{pending ? 'Logging in...' : 'Log in'}</button>;
}

// das Ergebnis des letzten Anmeldeversuchs
interface LoginState {
  error: string | null;
  login: string; // das eingegebene Login, um es erneut anzuzeigen
}

export default function App() {
  const [user, setUser] = useState<User | null>(null);
  const [doctors, setDoctors] = useState<Doctor[]>([]);
  const [captcha, setCaptcha] = useState<Captcha | null>(null);
  const [ready, setReady] = useState(false); // ist die anfängliche Prüfung beendet?
  const [serverError, setServerError] = useState<string | null>(null);

  async function loadCaptcha() {
    setCaptcha(await read<Captcha>('/api/captcha'));
  }

  async function loadDoctors() {
    setDoctors(await read<Doctor[]>('/api/doctors'));
  }

  // 1. wer ist angemeldet? 200 -> der Benutzer; 401 -> niemand
  useEffect(() => {
    async function checkSession() {
      try {
        setUser(await read<User>('/api/auth/me'));
        await loadDoctors();
      } catch (e) {
        if (!(e instanceof Response) || e.status !== 401) {
          setServerError('Is the RdvMedecins JSON server started (port 8080)?');
        } else {
          await loadCaptcha();
        }
      }
      setReady(true);
    }
    checkSession();
  }, []);

  // 2. das Login: eine ACTION, die den vorherigen Zustand und die
  // Daten des Formulars erhält und den neuen Zustand zurückliefert
  async function logIn(_previous: LoginState, data: FormData): Promise<LoginState> {
    const login = String(data.get('login'));
    const response = await fetch('/api/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' }, // der Body ist JSON
      body: JSON.stringify({ login, password: data.get('password'), captchaId: captcha?.id, captcha: data.get('captcha') }),
    });
    if (!response.ok) {
      // der JSON-Body der Fehlerantwort
      const error = (await response.json().catch(() => null)) as ApiError | null;
      const key = error?.key ?? 'ERRORS.SERVER_UNREACHABLE';
      await loadCaptcha(); // jedes Bild wird nur einmal verwendet
      return { error: `${response.status} - ${MESSAGES[key] ?? key}`, login };
    }
    setUser((await response.json()) as User);
    await loadDoctors();
    return { error: null, login };
  }
  const [state, loginAction] = useActionState(logIn, { error: null, login: 'admin' });

  // 4. der Logout
  async function logOut() {
    await fetch('/api/auth/logout', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: '{}' });
    setUser(null);
    setDoctors([]);
    await loadCaptcha();
  }

  let content;
  if (!ready) {
    content = <p className="text-muted">Checking the session...</p>;
  } else if (user) {
    // angemeldet
    content = (
      <div className="card p-3">
        <p>
          Logged in: <strong>{user.name}</strong> ({user.login}), role{' '}
          <span className="badge text-bg-primary">{user.role}</span>
        </p>
        <h2 className="h6">GET /api/doctors</h2>
        <ul>
          {doctors.map((m) => <li key={m.id}>{m.title} {m.firstName} {m.lastName}</li>)}
        </ul>
        <p className="small text-muted">Reload the page (F5): you remain logged in.</p>
        <button className="btn btn-outline-secondary align-self-start" onClick={logOut}>Log out</button>
      </div>
    );
  } else if (!serverError) {
    // nicht angemeldet: das Formular. Die Felder sind NICHT kontrolliert: name
    // bezeichnet sie in FormData; nach jeder Action setzt React sie auf
    // ihren Anfangswert zurück (defaultValue)
    content = (
      <form className="card p-3" action={loginAction}>
        <div className="mb-2">
          <label className="form-label" htmlFor="login">Login</label>
          <input id="login" name="login" className="form-control" autoComplete="username" defaultValue={state.login} />
        </div>
        <div className="mb-2">
          <label className="form-label" htmlFor="password">Password</label>
          <input id="password" name="password" type="password" className="form-control" autoComplete="current-password" />
        </div>
        <div className="mb-3">
          <label className="form-label" htmlFor="captcha">Type the characters of the image</label>
          <div className="d-flex align-items-center gap-3 mb-2">
            <div dangerouslySetInnerHTML={{ __html: captcha?.svg ?? '' }} />
            <button type="button" className="btn btn-link btn-sm" onClick={loadCaptcha}>Another image</button>
          </div>
          <input id="captcha" name="captcha" className="form-control" autoComplete="off" />
        </div>
        <LoginButton />
        <p className="small text-muted mt-2 mb-0">Accounts: admin, pelissier, martin... (password = login).</p>
        {state.error && <div className="alert alert-danger mt-3 mb-0">{state.error}</div>}
      </form>
    );
  }

  return (
    <div className="container py-4" style={{ maxWidth: 640 }}>
      <h1 className="h3 mb-3">Example 23 - logging in to the server</h1>
      {content}
      {serverError && <div className="alert alert-danger mt-3">{serverError}</div>}
    </div>
  );
}

    Der Ablauf (Zeilen 4–12): Beim Start wird der Server abgefragt, um festzustellen, wer angemeldet ist; dann folgen die Anmeldung, eine gesicherte Anfrage und die Abmeldung.

    • Zeilen 27–47: einige API-Typen, darunter die Form ALLER Fehler;
    • Zeilen 50–54: die wenigen Meldungen, die dieses Beispiel zur Übersetzung der Schlüssel des Servers benötigt (Beispiel 25 wird [i18next] verwenden);
    • Zeilen 57–63: eine kleine generische Funktion für GET-Anfragen: die JSON-Antwort, mit einem Typ; und wenn es kein 2xx ist, „werfen“ wir die Antwort selbst: Ihr Status zeigt, was zu tun ist;
    • Zeilen 67–70: die Schaltfläche zum Absenden des Formulars. [useFormStatus()] (aus [react-dom]) zeigt an, ob das Formular, das sie ENTHÄLT, gerade abgesendet wird: Es muss sich also um eine separate Komponente handeln, die innerhalb des Formulars platziert ist;
    • Zeilen 94–109: Beim Start wird [GET /api/auth/me] aufgerufen: Sind wir bereits angemeldet? Nach einem F5 hat der Client alles vergessen; der Server hingegen liest das Cookie. 200: der Benutzer; 401: niemand (dann wird ein CAPTCHA geladen); alles andere: Der Server antwortet nicht. Eine [async]-Funktion kann nicht selbst der Effekt sein (ein Effekt gibt sein Cleanup zurück, kein Promise): Wir deklarieren sie innerhalb des Effekts und rufen sie dann auf;
    • Zeilen 113–130: die Anmeldung, geschrieben als Aktion von [React] 19 (siehe unten). Sie erhält den vorherigen Zustand und die Formulardaten ([FormData]) und gibt den neuen Zustand zurück:
      • Zeile 114: [data.get(name)] liest ein Feld des Formulars, identifiziert über sein Attribut [name];
      • Zeilen 115–119: [POST /api/auth/login], mit einem JSON-Body: [method], dem Header [Content-Type] und dem Body, erzeugt von [JSON.stringify]. Bei Erfolg setzt der Server das [httpOnly]-Cookie aus dem JWT-Token: Unser Code sieht es NIEMALS (versuchen Sie es mit [document.cookie] in der Konsole: Es ist nicht vorhanden);
      • Zeilen 120–126: ein Fehlschlag: Der Body der Fehlerantwort, JSON, liefert den Meldungsschlüssel; jedes CAPTCHA-Bild wird nur einmal verwendet: Ein anderes wird geladen;
      • Zeilen 127–129: ein Erfolg: der Benutzer, gefolgt von einer geschützten Anfrage, [GET /api/doctors]: Der Browser fügt das Cookie automatisch bei (gleicher Ursprung);
    • Zeile 131: [useActionState(action, initialState)] ([React] 19) liefert den Zustand, der von der letzten Ausführung der Aktion erzeugt wurde, und eine Version der Aktion, die an das Formular übergeben wird;
    • Zeilen 134–139: Abmeldung; [POST /api/auth/logout]: Der Server löscht das Cookie. Jeder POST muss einen JSON-Body haben (der Server lehnt andere ab; siehe das vorherige Kapitel): ['{}'];
    • Zeile 165: [<form action={function}>]: Ab [React] 19 kann das Attribut [action] eines Formulars eine Funktion akzeptieren. Beim Absenden [React] verhindert es, dass der Browser das Formular absendet, fasst die Felder in einem [FormData] zusammen und ruft die Funktion auf; während deren Ausführung [useFormStatus] „in Bearbeitung“ anzeigt. [onSubmit], [preventDefault] und ein Status pro Feld sind nicht mehr erforderlich;
    • Zeilen 168–180: Die Felder sind nicht kontrolliert: Sie werden über ihren [name] identifiziert. Nach jeder Aktion setzt [React] das Formular zurück: Jedes Feld kehrt zu seinem Anfangswert zurück ([defaultValue]). Die Felder für Passwort und CAPTCHA werden daher geleert; das Login-Feld kehrt zu dem Wert zurück, der von der Aktion im Zustand gespeichert wurde ([state.login]), also dem soeben eingegebenen;
    • Zeile 184: die Fehlermeldung, die von der letzten Aktion erzeugt wurde.

// common/api-error.ts - EINE Klasse für alle Fehler der API
// -------------------------------------------------------------------------
// Alle Fehlerantworten des RdvMedecins-Servers haben dieselbe Form:
//   { "statusCode": 409, "key": "ERRORS.LOGIN_TAKEN", "params": {...}, "fields": {...} }
// Eine Anfrage kann aber auch ANDERS scheitern: gar keine Antwort
// (Netzwerk ausgefallen: fetch wirft einen TypeError) oder eine Antwort, die
// nicht von unserem Server stammt (eine Fehlerseite des Vite-Proxys, wenn der
// JSON-Server gestoppt ist). All das wird in EINE Klasse umgewandelt,
// ApiError, die den vom Server gesendeten Übersetzungsschlüssel trägt (und,
// falls vorhanden, dessen Parameter und den Fehler jedes Feldes).
// =========================================================================

export class ApiError extends Error {
  readonly statusCode: number; // 0: Der Server hat nicht geantwortet
  readonly key: string; // z. B.: 'ERRORS.LOGIN_TAKEN'
  readonly params: Record<string, string>;
  readonly fields: Record<string, string>;

  constructor(statusCode: number, key: string, params: Record<string, string> = {}, fields: Record<string, string> = {}) {
    super(key);
    this.name = 'ApiError';
    this.statusCode = statusCode;
    this.key = key;
    this.params = params;
    this.fields = fields;
  }
}

// eine Fehlerantwort (4xx, 5xx) -> ein ApiError
export async function fromResponse(response: Response): Promise<ApiError> {
  // der JSON-Body des Fehlers, falls vorhanden und von der richtigen Form
  let body: { key?: string; params?: Record<string, string>; fields?: Record<string, string> } = {};
  try {
    const json: unknown = await response.json();
    if (typeof json === 'object' && json !== null) {
      body = json;
    }
  } catch {
    // kein JSON: Es hat nicht unser Server geantwortet
  }
  // kein Schlüssel: Der Proxy oder das Netzwerk hat an seiner Stelle geantwortet
  const key = body.key ?? (response.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR');
  return new ApiError(response.status, key, body.params, body.fields);
}
    • Zeilen 14–28: EINE Klasse für alle API-Fehler: den HTTP-Status (0: keine Antwort), den vom Server gesendeten Übersetzungsschlüssel, seine Parameter und den Fehler zu jedem Feld eines abgelehnten Formulars. Sie erbt von [Error]: Sie kann geworfen ([throw]) und erkannt ([instanceof ApiError]) werden. Die „Property-Parameter“ von [TypeScript] ([constructor(public readonly key: string)]) werden nicht verwendet: Die Option [erasableSyntaxOnly] von [tsconfig.json] deaktiviert sie, weil sie Code erzeugen;
    • Zeilen 31–45: Eine Fehlerantwort wird zu einem [ApiError]. Der Body stammt nicht immer als JSON von unserem Server: Wenn der JSON-Server nicht läuft, antwortet der Proxy von [Vite] ohne JSON-Body. Kein Schlüssel: Ein Statuscode von 500 oder höher bedeutet „Server nicht erreichbar“.

// -------------------------------------------------------------------------
// In Beispiel 23 wiederholte jede Anfrage dieselben Handgriffe: Präfix
// /api, JSON-Header, Test von response.ok, Lesen des Fehler-Bodys... Sie
// sind hier zusammengefasst:
//
//   const doctors = await api.get<Person[]>('/doctors');
//   await api.post('/appointments', { day, slotId, clientId });
//
//   - bei Erfolg liefert das Promise den JSON-Body, TYPISIERT;
//   - bei einem Fehler wird es mit einem ApiError ABGELEHNT.
// Alle Anfragen laufen über die Funktion request: Sie ist der Ort,
// an dem ein ihnen allen GEMEINSAMES Problem behandelt würde (vgl. die Fallstudie und die
// Antwort 401). Verwendet von den Beispielen 24 und 25.

import { fromResponse, ApiError } from './api-error';

export async function request<T>(method: string, url: string, body?: unknown): Promise<T> {
  let response: Response;
  try {
    response = await fetch(`/api${url}`, {
      method,
      // ein JSON-Body (der Server weist ein POST ab, das keinen hat)
      headers: body === undefined ? {} : { 'Content-Type': 'application/json' },
      body: body === undefined ? undefined : JSON.stringify(body),
    });
  } catch {
    // fetch hat KEINE Antwort erhalten (Netzwerk, Server gestoppt)
    throw new ApiError(0, 'ERRORS.SERVER_UNREACHABLE');
  }
  if (!response.ok) {
    throw await fromResponse(response);
  }
  return (await response.json()) as T;
}

  put: <T>(url: string, body: unknown) => request<T>('PUT', url, body),
  delete: <T>(url: string, body?: unknown) => request<T>('DELETE', url, body),
};

function tomorrow(): string {
  const d = new Date(Date.now() + 24 * 3600 * 1000);
  return `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;
}

function timeRange(c: ScheduleSlot): string {
  const hm = (h: number, m: number) => `${h}:${String(m).padStart(2, '0')}`;
  return `${hm(c.startHour, c.startMinute)} - ${hm(c.endHour, c.endMinute)}`;
}

}

import { useTranslation } from 'react-i18next';
import { api } from '../../common/api';
import LoginBar from '../../common/LoginBar';
import { ApiError } from '../../common/api-error';
import type { Person, User } from '../../common/types';
import { useConfirmation } from '../../16-confirmation/src/confirmation/confirmation';

interface ClientInput {
  title: string;
  firstName: string;
  lastName: string;
  login: string;
  password: string;
  version: number;
}
type Field = keyof ClientInput;

const EMPTY: ClientInput = { title: 'Mr', firstName: '', lastName: '', login: '', password: '', version: 0 };

interface Message {
  key: string;
  params?: Record<string, string>;
}

  const confirm = useConfirmation();

    setSuccess(null);
