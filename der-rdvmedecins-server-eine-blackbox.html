    7. Der RdvMedecins-Server, eine Blackbox

    Die Beispiele 22 bis 25 sowie die Fallstudie interagieren mit einem Server: dem JSON-Server der Anwendung [RdvMedecins]. Es ist der [NestJS]-Server aus der vorherigen Lektion, dessen Controller keine HTML-Seiten mehr erzeugen, sondern JSON-Antworten liefern. Seine Geschäfts- und Datenzugriffsschichten bleiben unverändert.

    In diesem Kurs ist dieser Server eine Blackbox: Wir müssen nicht wissen, wie er geschrieben ist. Wichtig ist allein seine API – das heißt die Liste der HTTP-Anfragen, die er akzeptiert, und der Antworten, die er zurückgibt. Das ist die typische Situation eines Client-Entwicklers: Die API ist ein Vertrag, und das Serverteam kann hinter diesem Vertrag ändern, was es will. Sein Quellcode wird mitgeliefert (Ordner [rdvmedecins-nestjs-json]) und ist für den neugierigen Leser ausführlich kommentiert.

    Dieses Kapitel erklärt, wie der Server installiert wird, beschreibt seine API und fragt ihn mit [curl] ab.

    7.1. Die Anwendung RdvMedecins

    Die Anwendung verwaltet die Termine einer Arztpraxis. Sie kennt drei Rollen:

    Rolle
    Wer
    Was sie tun können
    [ADMIN]
    Der Administrator ([admin])
    Termine für alle Patienten vereinbaren und stornieren; Ärzte und Klienten verwalten
    [DOCTOR]
    Ärzte ([pelissier], [tatou], [dupont])
    Termine für alle Patienten vereinbaren und stornieren; alle Namen in den Terminkalendern sehen
    [USER]
    Patienten ([martin], [durand], [bistrou], [german])
    Termine für sich selbst buchen; ihre Termine stornieren; ihr Konto verwalten. In einem Terminkalender sehen sie die Namen anderer Patienten nicht

    Die Demo-Konten verwenden ihren Login als Passwort. Die Verwaltungsregeln werden vom Server unabhängig vom Client überprüft:

    • keine Termine in der Vergangenheit;
    • nur ein bevorstehender Termin pro Patient;
    • ein Zeitfenster kann pro Tag nur einmal gebucht werden;
    • zwei Ärzte (oder zwei Klienten) dürfen nicht denselben Vor- und Nachnamen haben; ein Login gehört nur zu einem Konto;
    • ein Arzt mit Terminen kann nicht gelöscht werden;
    • ein Datensatz, der zwischenzeitlich von jemand anderem geändert wurde, kann nicht überschrieben werden (optimistisches Sperren);
    • einem Patienten wird nie der Name eines anderen Patienten zugewiesen.

    7.3. Antwortformat

    Alle URLs beginnen mit [/api]. Eine erfolgreiche Anfrage erhält einen 2xx-Statuscode und im Body die angeforderten Daten im JSON-Format. Eine abgelehnte Anfrage erhält einen 4xx- oder 5xx-Code und im Body einen Fehler, der IMMER dasselbe Format hat:

    1
2
3
4
5
6
    {
  "statusCode": 400,
  "key": "ERRORS.INVALID_FORM",
  "params": { "min": "6" },
  "fields": { "lastName": "ERRORS.LASTNAME_REQUIRED", "password": "ERRORS.PASSWORD_TOO_SHORT" }
}
    • [statusCode]: der HTTP-Code, im Body wiederholt;
    • [key]: der Übersetzungsschlüssel der Meldung. Der Server liefert nie anzuzeigenden Text zurück: Er kennt die Sprache des Benutzers nicht mehr. Der Client übersetzt den Schlüssel anhand seiner Wörterbücher (siehe Beispiel 21);
    • [params] (optional): die Parameter der Meldung ([At least {min} characters], [Try again in {minutes} minute(s)]);
    • [fields] (optional): bei einem abgelehnten Formular der Fehler zu jedem Feld.

    Verwendete Codes:

    7.4. Authentifizierung

    Der Client authentifiziert sich mit [POST /api/auth/login], unter Angabe von Benutzername, Passwort und CAPTCHA-Antwort. Als Gegenleistung legt der Server ein Cookie im Browser ab, das ein signiertes JWT-Token enthält:

    1
    Set-Cookie: rdvmedecins_jwt=eyJhbGciOiJIUzI1NiIs...; Max-Age=7200; Path=/api; HttpOnly; SameSite=Strict

    Seine Attribute sind für die Sicherheit wichtig:

    • [HttpOnly]: Der [JavaScript]-Code der Seite kann dieses Cookie nicht lesen. Ein bösartiges Skript, das möglicherweise in die Seite eingeschleust wurde, könnte das Token daher nicht stehlen. Folge für den Client: Er kann nicht selbst feststellen, ob er angemeldet ist. Er fragt den Server ([GET /api/auth/me]);
    • [Path=/api]: Der Browser fügt es nur Anfragen an die API bei;
    • [SameSite=Strict]: Der Browser fügt dieses Token nur Anfragen bei, die VON einer Seite dieser Website gesendet werden. Eine bösartige Seite auf einer anderen Website kann den Browser nicht dazu bringen, im Namen des Benutzers zu handeln (ein sogenannter CSRF-Angriff);
    • [Max-Age=7200]: Es läuft nach zwei Stunden ab, zeitgleich mit dem Token.

    Der Browser sendet dieses Cookie dann automatisch mit jeder Anfrage an [/api]. Der [React] -Client muss daher nichts unternehmen, um sich zu authentifizieren, sofern seine Seiten und die API denselben Ursprung haben (gleiches Protokoll, gleicher Rechner, gleicher Port). Das ist die Aufgabe des Proxys des Entwicklungsservers [Vite] (siehe Beispiel 22) und in der Produktion des Servers selbst (siehe Kapitel „Deployment“).

    Eine zweite Schutzmaßnahme gegen CSRF-Angriffe: Der Server lehnt (415) jede POST-Anfrage ab, deren Body nicht im JSON-Format vorliegt. Ein kompromittiertes HTML-Formular auf einer anderen Website kann kein JSON senden.

    • [free]: Ist das Zeitfenster an diesem Tag frei?

    7.6. Die API mit curl abfragen

    Der Ordner [curl] auf dem Server enthält die JSON-Bodys der Anfragen dieses Kapitels, eine Datei pro Anfrage. Zum Beispiel [curl/login-admin.json]:

    1
    { "login": "admin", "password": "admin", "captchaId": "-", "captcha": "test" }

    Die Befehle werden in einer Konsole eingegeben, die im Verzeichnis [rdvmedecins-nestjs-json] geöffnet ist. Einige Optionen von [curl]:

    • [-i]: zusätzlich die Antwort-Header anzeigen; [-s]: ohne Fortschrittsanzeige;
    • [--json @file]: den Inhalt der Datei per POST senden, mit dem Header [Content-Type: application/json] (curl 7.82 und höher; bei einer älteren Version verwenden Sie [-H "Content-Type: application/json" -d @file]);
    • [-X PUT], [-X DELETE]: die HTTP-Methode;
    • [-c cookies.txt]: die empfangenen Cookies in dieser Datei speichern; [-b cookies.txt]: sie zurücksenden. So „bleibt“ [curl] von einem Befehl zum nächsten „angemeldet“, genau wie ein Browser.

    Unter [PowerShell] müssen Sie [curl.exe] eingeben und nicht [curl] (das dort auf einen anderen Befehl verweist). Die etwas langen JSON-Antworten wurden für dieses Dokument formatiert, und die Header [Date], [ETag], [Connection], und [Keep-Alive] wurden entfernt.
